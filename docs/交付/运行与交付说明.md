# 掼蛋 Agent 运行与交付说明

本项目使用本地 OpenGuanDan 官方源码快照、Python 规则工具和 LangGraph 调用现有 DeepSeek 模型。V0 为规则策略，V1 为一次主决策，V2 在满足条件时增加一次复核或修复。项目没有训练或微调模型。

本文的命令从**项目根目录**执行。B10 的冻结配置、比赛结果和清洁目录复现证据以[实验报告](实验报告.md)为准。历史调用预算不自动补充，重新运行真实模型实验会产生新的请求与记录。

GitHub 检出目录请优先阅读[快速开始](../快速开始.md)。本文同时保留本地课程交付包的说明；文中 `artifacts/`、B10 `runs/`、PPT 和 ZIP 不随公开仓库提供，公开摘要见[证据说明](../evidence/README.md)。平台快照需要先通过 `uv run --locked python -m scripts.fetch_platform` 自行获取。

## 2. 环境准备

Python 使用 3.12.13，依赖以 `uv.lock` 为准。Java 平台构建需要 JDK 21 和 Maven。首次安装依赖需要联网；`--offline` 只适用于依赖已经存在的机器，不应放进全新机器的首装命令。

```sh
uv sync --locked --cache-dir runtime/uv-cache
uv run --locked --cache-dir runtime/uv-cache guandan-agent --version
uv run --locked --cache-dir runtime/uv-cache guandan-agent config-check configs/local.example.toml
uv run --locked --cache-dir runtime/uv-cache pytest
```

`config-check` 不连平台、不加载 `.env`、不调用模型。普通测试使用固定数据及 HTTP Mock，网络连接由测试约束阻止。安装失败时保留错误信息并检查 Python 版本和网络，不要改锁文件绕过问题。

## 3. 无密钥页面演示

下面使用已有固定数据展示牌桌和决策面板，没有新比赛或模型请求：

```sh
uv run --locked --cache-dir runtime/uv-cache python scripts/serve_b08_demo.py
```

浏览器打开 `http://127.0.0.1:18080`，结束后 Ctrl-C 停止服务。固定演示数据不计入 B10 对战结果。

浏览已有真实归档时使用正式入口：

```sh
uv run --locked --cache-dir runtime/uv-cache guandan-agent serve
```

打开 `http://127.0.0.1:8000`。服务默认只在本机监听。阅读历史不需要 Java 服务，页面启动新的 V0 比赛才需要。只有显式加入允许列表的配置可以由页面启动。

## 4. 构建和启动本地官方平台

固定提交为 `e92db7fa9d915fb318b3be78703d5ccd4a09c887`。`scripts/prepare_platform.py` 会同时检查以下两份材料：

- `research/archives/OpenGuanDan-Simulator-e92db7f.tar.gz`
- `research/sources/OpenGuanDan-Simulator-e92db7f/`

它校验归档 SHA-256，并将源码逐文件与归档比对。只提供 Python wheel 无法完成 Java 平台构建。本次本地交付包仅选入这份必要快照及其归档，研究目录中其他论文、项目、数据集与缓存都不纳入。

```sh
uv run --locked --cache-dir runtime/uv-cache python scripts/prepare_platform.py \
  --java-home /Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
```

其他机器将 `--java-home` 改为本机 JDK 21 的根目录。脚本只在 `runtime/platform/` 建副本和 Maven 缓存，并将服务绑定到 `127.0.0.1`，不修改原始快照。平台快照未发现独立 LICENSE 文件，应沿用课程授权范围，不能由本项目材料推断公开再分发权限。第三方来源见[来源与使用范围](来源与使用范围.md)。

第一个终端启动服务，以下以 macOS 的 JDK 路径为例：

```sh
cd runtime/platform/workspace/guandan-websocket
/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home/bin/java \
  -Dserver.port=18181 -jar target/guandan-java-pure-1.0.0.jar
```

第二个终端回到项目根目录，执行 V0 短演示：

```sh
uv run --locked --cache-dir runtime/uv-cache guandan-agent run \
  configs/local.example.toml --max-runtime-s 120
```

该命令会新建记录。到达 120 秒而没有整场结算时，记录为受控中断，不能当作输赢。V0 不调用模型，也不需要 API 密钥。演示结束后停止自己启动的 Java 服务。

## 5. V1/V2 模型运行

线上模型默认 `deepseek-flash`、关闭思考、零自动重试。当前 High 实验使用隔离 Provider 和更宽的时间/输出预算，不能将 High 实验配置直接填进正式 `RunConfig`。

本地复制空配置并自行填入密钥：

```sh
cp .env.example .env
```

不要把密钥写进 TOML、源码、命令参数或报告。正式 CLI 只读取进程中的 `DEEPSEEK_API_KEY`；需要 `.env` 时由 `uv --env-file .env` 加载。B10 的 live 入口和额度由冻结清单统一约束，本说明不提供绕过已耗尽批次预算的重跑指令。

需重新实验时先复制形成**新批次**，确定总调用数、单次超时、输出上限、失败停止条件和输出目录，再执行 live。失败请求占用额度，V2 的 review 与 repair 共用第二次机会，不通过更换目录自动补额。

## 6. 查看与重算已有结果

每场记录包含 `config.json`、`events.jsonl`、`summary.json`，报告另存 `reports/`。先查看 `summary.json` 中完成状态、日志完整性、未确认提交和未完成调用，再查看成绩。发送成功与平台确认分开记录。

下例只重算本批 B10 V0 统计，不调用模型：

```sh
uv run --locked --cache-dir runtime/uv-cache guandan-agent evaluate \
  runs/773cc7f3-a171-4f99-8a84-8199d6ff55a7 --unit match
```

用 B10 的实际 run 路径替换即可重算对应比赛。输出为新的统计报告，不覆盖源配置、事件和汇总。离线复盘自己的用量不混入线上统计；未知 Token 或费用继续显示未知。

三条决策路径的源码与演示证据见[证据索引](证据索引.md)。固定脚本可解释分支行为，真实比赛确认用于证明平台执行，两者不能互相替代。

## 7. 交付边界

只打包必要源码、锁文件、空凭证样例、配置、文档、明确选择的证据和被授权的平台材料。排除 `.env`、API 密钥、`.venv`、`runtime` 缓存、IDE 配置、整份 `research` 和与结论无关的大批历史运行。清单逐文件列出大小和摘要，脱敏检查的结论对应实际交付包。

个人报告由本人核对并填写。当前模板中的 A/B/C 是责任角色，不代表真实人员，也不构成个人工作量证明。小组 PPT 和实验报告可用于演示，正式提交仍需补齐姓名、学号、课程信息及教师指定格式。
