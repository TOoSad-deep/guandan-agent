# 答辩讲稿与演示顺序

建议用 8—10 分钟讲清问题、实现、实测和限制，再留答疑。时间是建议，不是课程硬性要求。成员姓名与课程信息由小组填写，PPT 不冒用 A/B/C 为真实姓名。

## 讲解主线

1. 项目解决什么问题：通过现有模型和有限调用流程参与掼蛋，程序负责合法性、状态和执行。
2. 为什么保留规则工具：平台给动作，工具分析本人余牌，模型在候选中权衡。模型自行数牌曾出错，因此精确张数由程序提供。
3. LangGraph 的实际作用：V1 一次主决策，V2 仅在关键风险时复核，格式/候选错误时允许一次修复，review 与 repair 共用第二次机会。
4. 如何可靠执行：请求/候选快照绑定，截止前校验，零自动重试，异常规则兜底，发送与平台确认分别记录。
5. B10 实际发生了什么：只讲实验报告中的实际数据，同时报调用覆盖、失败、规则降级与未确认，不从一场胜负推断稳定强弱。
6. 文字为什么仍需核对：High 24 次定向复测改善为 21/1/2，但仍有数牌错误，最慢 39.96 秒，不能直接替代在线生产参数。

## 演示顺序

先运行无密钥固定页面演示，展示本人手牌、公开余牌、候选和确认状态。明确它是固定展示数据。随后打开 B10 的实际归档，定位一条正常主决策；定位本批 V2 自然复核的同请求 main、review、提交和确认。再展示预算耗尽的真实规则兜底；超时或格式错误分支用已有测试解释，并标注测试环境。

按证据查看三个点：动作 ID 属于当时的候选；原始提交与平台反馈对应；模型理由和程序说明分别展示。页面上模型文字不等于事实，程序事实可回到原日志核对。

不要在答辩现场临时开启不限额模型实验。现场优先使用闭合归档，若演示新 V0 比赛，采用明确运行上限，超时中断如实展示。系统运行命令见[运行与交付说明](运行与交付说明.md)。

## 可能被问到的问题

| 问题 | 基于当前实现可回答的内容 |
| --- | --- |
| 为什么不训练模型？ | 课程范围采用现成模型，重点是工具、状态、执行权限、有限复核与可重算评测。没有训练指标可汇报。 |
| 为什么不是一个 API 调用？ | 多座位事实隔离、合法候选计算、请求绑定、统一预算、复核/修复分支、超时提交和平台确认构成完整执行系统。 |
| V2 一定更强吗？ | 尚不能证明。改选不等于纠错，一场结果和非配对发牌不足以得出稳定胜率结论。 |
| 模型说错是否会出非法牌？ | 输出只允许候选 ID，程序再次验证当前请求归属与合法性；解释错和动作非法分开统计。 |
| High 为什么不直接在线使用？ | 该实验放宽到 90 秒，出现 39.96 秒单次调用，超过当前 20 秒模型超时与 30 秒总决策预算。 |
| 能读其他人的牌吗？ | 策略输入仅有本人手牌和公开信息，其他座位隐藏手牌不进入本玩家输入。 |
| 谁完成了哪些工作？ | 依据每位成员本人核对的个人报告回答，角色计划和 AI 协助记录不能代替个人实际贡献。 |

## 报告时避免的误读

测试通过、API 成功、动作合法、平台确认、文字正确、策略更强是不同结论。整场已完成不代表所有步骤都用模型；有限额度耗尽后会转规则，必须说明覆盖率。没有费用证据时报告 tokens 和未知费用，不按想象填金额。
