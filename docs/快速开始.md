# 快速开始

所有命令从仓库根目录执行。先体验无密钥页面，再按需准备 Java 平台和模型配置。

以下单行命令适用于 macOS、Linux 和 Windows PowerShell。Windows 建议使用 PowerShell；不需要 WSL，也不需要手动激活 `.venv`。项目已加入三系统 CI 配置，实际通过状态以对应提交的 Actions 结果为准。

## 1. 安装 Python 环境

需要 [uv](https://docs.astral.sh/uv/getting-started/installation/)，Python 固定为 `.python-version` 中的 3.12.13。依赖版本与下载来源由 `uv.lock` 锁定。

Windows PowerShell 先为当前终端启用 Python UTF-8 模式，确保历史脚本和测试中的中文文件不受系统代码页影响；每次新开终端需要重新设置：

```powershell
$env:PYTHONUTF8 = '1'
```

```sh
git clone https://github.com/TOoSad-deep/guandan-agent.git
cd guandan-agent
uv sync --locked
uv run --locked guandan-agent --version
uv run --locked guandan-agent config-check configs/local.example.toml
```

`config-check` 只读 TOML，显示生效配置和 `config_id`，不读取 `.env`、连接平台或调用模型。不要通过修改锁文件解决临时网络问题。

## 2. 无密钥页面演示

```sh
uv run --locked python scripts/serve_b08_demo.py
```

打开 [http://127.0.0.1:18080](http://127.0.0.1:18080)，可查看牌桌、决策与固定复盘数据，按 Ctrl-C 停止。端口被占用时可附加 `--port 18081`。这是读取 `tests/fixtures/web/` 的固定演示，不需要 Java、API 密钥或新对局。

## 3. 获取固定平台并运行测试

公开仓库不携带第三方源码。获取脚本只下载固定提交、验证摘要并还原文件，不运行下载的代码。

```sh
uv run --locked python -m scripts.fetch_platform
uv run --locked pytest
uv build
```

上游：[OpenGuanDan-Simulator](https://github.com/GameAI-NJUPT/OpenGuanDan-Simulator)。固定提交：`e92db7fa9d915fb318b3be78703d5ccd4a09c887`；归档 SHA-256：`cb4015c37a4c19e5e6f59d856ee98e1d5a3f5708e46f86411ee4267e790fddc5`。

下载后分别放到 `research/archives/OpenGuanDan-Simulator-e92db7f.tar.gz` 和 `research/sources/OpenGuanDan-Simulator-e92db7f/`。已存在的有效快照只校验，不重复下载；本地内容改变时拒绝覆盖。摘要不匹配时先检查网络和来源，不要改常量跳过检查。

`pytest` 使用固定回放与 Mock，不启动真实对局或调用模型，并主动阻止网络连接；已构建 Java 动作工具时会启动本地 worker 做检查。它会检查平台快照和原始文件，故需先获取平台。`uv build` 生成 `dist/` 下的 wheel/sdist，安装包只包含正式 Python 包及必要安装文件，页面演示脚本与平台构建需在 Git 检出目录执行。

## 4. 构建 Java 平台

需要 **JDK 21（java 和 javac）及 Maven**。首次 Maven 构建需要下载依赖。安装后重新打开终端，确保 Maven 的 `bin` 目录已加入 `PATH`。

Windows PowerShell 设置当前终端的 JDK，路径替换为实际安装目录（不是 `bin` 目录）：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\jdk-21'
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
javac -version
mvn -version
```

macOS 可用以下命令选择 JDK 21：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
export PATH="$JAVA_HOME/bin:$PATH"
```

Linux 同样设置 `JAVA_HOME` 为本机 JDK 21 目录，并将 `$JAVA_HOME/bin` 加入 `PATH`。

三系统使用相同的构建命令：

```sh
uv run --locked python scripts/prepare_platform.py
```

构建按 `--java-home` → `JAVA_HOME` → 已存在的本项目 macOS JDK 21 目录 → `PATH` 中的 `javac` 查找 JDK，并核对 Java、javac、Maven 均使用 21。Windows 自动使用 `java.exe`、`javac.exe`，并从 `PATH` 查找 Maven（包括 `mvn.cmd`）。也可显式传入带引号的路径，例如 PowerShell：

```powershell
uv run --locked python scripts/prepare_platform.py --java-home "$env:JAVA_HOME"
```

`--java-home` 仅影响本次构建；启动 Agent 和 Java 服务的终端仍需正确设置 `JAVA_HOME` 和 `PATH`。运行时优先使用 `JAVA_HOME`，然后使用已有的本项目 macOS JDK 21，最后使用 `PATH` 中的 Java。

脚本在 `runtime/platform/` 创建运行副本和 Maven 缓存，只将副本的服务监听改为本机地址。它不改原始快照，也不启动对局。依赖齐全后可使用 `--offline`；全新安装不要直接加此参数。

## 5. 启动 V0 规则比赛

终端 A 从项目根目录启动刚构建的服务，确保此处的 `java` 来自 JDK 21：

```sh
java "-Dserver.port=18181" -jar runtime/platform/workspace/guandan-websocket/target/guandan-java-pure-1.0.0.jar
```

终端 B 执行四座位 V0，最多运行 120 秒：

```sh
uv run --locked guandan-agent run configs/local.example.toml --max-runtime-s 120
```

V0 不读取模型密钥、不发模型请求。日志写入 `runs/<run_id>/`；Ctrl-C 或达到演示时长后受控关闭。未取得整场结算的中断不能计作输赢，CLI 可能以非零状态结束。结束后停止自己启动的 Java 服务。

浏览新记录：

```sh
uv run --locked guandan-agent serve
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。默认本机监听，页面仅允许启动指定配置。运行结束并完成归档后，决策列表读取归档中的历史；查看已有记录不需要保持 Java 服务运行。

## 6. V1/V2 与模型配置

正式 CLI 从进程环境读取 `DEEPSEEK_API_KEY`。可先复制空样例并在本机编辑：

```sh
cp .env.example .env
cp configs/local.example.toml configs/my-v1.toml
```

Windows PowerShell 中可将 `cp` 换成 `Copy-Item`；这些复制命令在两种 shell 中语义相同。

在 `configs/my-v1.toml` 中把 `[run] policy` 改为 `"V1"` 或 `"V2"`，为一个新实验明确设置 `[batch] max_model_calls`，例如先用 `2`。四个座位共用 run 额度；V2 每步至多两次，失败调用也占额度。仅想让一个座位使用模型时，参考 `configs/b10-v1.toml` 的逐座位 policy 配置，并另存为新的 development 配置。

先检查再启动；启动前需要第 5 节的 Java 服务：

```sh
uv run --locked guandan-agent config-check configs/my-v1.toml
uv run --locked --env-file .env guandan-agent run configs/my-v1.toml --max-runtime-s 120
```

第二条命令会消耗真实 API 额度。模型名、超时和输出限制以 TOML 为准，`.env` 中的历史探针变量不覆盖正式 `RunConfig`。在线默认关闭思考、不重试。High 文本实验使用了更宽的超时和输出预算，不能直接当在线生产配置。

`b06`、`b09`、`b10` 等历史配置用于记录已完成实验；历史批次的 live 额度已使用，另开实验应有新的配置、额度、输出路径和停止条件。

## 7. 统计与离线复盘

在页面选择已结束的运行，进入“复盘与统计”，点击“生成统计报告”即可根据日志生成统计并打开结果，**不调用模型**。固定演示页面的归档只读，禁用此生成操作。

需要模型分析时，加载已有密钥后启动页面服务：

```sh
uv run --locked --env-file .env guandan-agent serve
```

进入“复盘与统计”，选择复盘座位，点击“生成模型复盘”。每份报告调用模型至多 **1 次**，自动选取该座位最多 **3 条关键决策**；页面显示剩余额度、生成状态，完成后打开报告。它不覆盖整场所有决策。普通浏览、刷新报告和生成统计不会触发模型。

页面模型复盘使用独立配置 `configs/web-review.toml`：默认 DeepSeek Flash、20 秒调用超时、不重试，服务生命周期内共用 **10 次**离线调用额度。失败的已预留调用也可能消耗额度。可在启动前调整配置，或用 `serve --review-config YOUR_CONFIG.toml` 指定 `configs/` 下的其他固定配置；页面不能提交密钥或任意调用额度。缺少复盘配置时该功能禁用，缺少密钥时生成会显示错误。在线运行期间不能开始离线模型复盘。

对自己的已关闭归档重算统计，不需要模型：

```sh
uv run --locked guandan-agent evaluate runs/YOUR_RUN_ID --unit match
```

将 `YOUR_RUN_ID` 替换为实际目录。统计会区分整场与小局，保留中断、未确认和缺失值。通过 CLI 新生成报告后，点击页面的“刷新报告”导入最新文件，无需重启服务；普通浏览已有报告不会生成新报告。

检查离线复盘计划：

```sh
uv run --locked guandan-agent review configs/offline-facts.example.toml runs/YOUR_RUN_ID
```

没有 `--live` 不生成模型回复。通过 CLI 生成真实复盘时，需另存新配置并设置有限的 `[offline] max_model_calls`，加载密钥后显式附加 `--live`。完成后同样点击“刷新报告”。程序事实会重新对照源记录；模型分析和建议仍需人工核对。

## 8. 加入老师提供的 OpenGuanDan 房间

远端对打由本机 Python Agent 连接老师的游戏服务，本机网页负责启动、观察与查看记录。无需另起本地 Java WebSocket 游戏服务；已经构建的本地 Java 动作分析工具仍可使用。

先向老师确认完整 `ws://` 或 `wss://` 地址（含端口和路径）、房间号、分配座位、`userId`、每步出牌时限，以及是否允许调用外部模型。当前适配针对仓库固定的 OpenGuanDan 版本，老师修改过协议时需要额外核对。拿到实际地址前，配置校验不代表已经接入老师服务器。

复制专用模板：

```sh
cp configs/classroom-join.example.toml configs/classroom-join.toml
```

编辑 `configs/classroom-join.toml`：

| 字段 | 现场填写 |
| --- | --- |
| `platform.url` | 老师给的完整 WebSocket 地址，不能填本机 `127.0.0.1` 或普通网页地址 |
| `platform.mode` | 保持 `"join"` |
| `platform.room_id` | 老师给的房间号 |
| `run.seats` | 只列老师分给本机控制的座位，编号为 0—3 |
| `run.seats[].user_name` | 老师分配或同意使用的身份；协议里实际发送为 `userId` |
| `run.evaluation_team` | 0/2 席为队伍 0，1/3 席为队伍 1；用于结果统计 |
| `decision.total_s` | 按老师的单步时限调整，留出网络余量 |

模板里的地址、房间、身份和座位都是示例，必须替换。18 秒总预算、12 秒模型超时仅是“服务端至少给 20 秒”时的示例，不能当作老师的已确认时限。`matches=1` 表示这一场完整比赛，可能包含多个小局。

单席只保留一个 `seats` 元素。若本机负责一队的两个席位，可以配置 0/2 或 1/3 两项，每项身份不同；不要沿用本地四席自玩的设置。配置会生成独立座位连接，不共享其他席位的隐藏手牌。

先用模板的 V0、零调用额度，在老师安排的联通测试房间检查接入。正式使用 V1/V2 时，在开局前同时设置 `run.policy`、非零的 `[batch] max_model_calls` 和合适的时限，并加载 `.env`。V2 主决策和复核共用在线额度，多个受控座位也共用额度；耗尽后使用规则备选。网页模型复盘的额度与在线打牌额度分开。

完成编辑后校验并启动专用网页：

```sh
uv run --locked guandan-agent config-check configs/classroom-join.toml
uv run --locked --env-file .env guandan-agent serve --port 8001 --allow-config classroom-join.toml
```

V0 不需要密钥，可省略 `--env-file .env`。打开 [现场工作台](http://127.0.0.1:8001)，选择“新运行 / 未选择”，确认启动配置为 `classroom-join.toml`，得到老师开局指示后点击“新建运行”。固定上游实现四席到齐后自动开局；入座成功但尚未发牌通常是在等其他席位，老师的修改版以现场说明为准。

网页服务在启动时读取并冻结配置。**修改地址、房间或座位后，要重启 8001 服务才能使用新配置。** 配置校验与打开网页不会加入房间，点击“新建运行”才连接。保持服务终端运行，不要重复启动同一座位。

若只需要终端运行，可以用下列命令代替网页启动。两种方式只选一种；终端对局不会实时出现在另一个网页进程中：

```sh
uv run --locked --env-file .env guandan-agent run configs/classroom-join.toml
```

正式对打不要附加演示用的 `--max-runtime-s 120`，该参数会到时主动停止。当前客户端不自动重连；中途断线或入座失败时先检查房间、座位和网络，与老师确认是否重开，避免重复加入旧局。比赛完成后，当前网页可查看决策、统计和模型复盘。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `Pinned archive missing` | 先执行 `python -m scripts.fetch_platform`；单独 wheel 不含平台源码 |
| 摘要不匹配或源码被改动 | 保留本地修改，核对上游固定提交；不要改 SHA 常量或覆盖原记录 |
| Maven/JDK 版本错误 | 确认 `--java-home`、`java -version`、`javac -version` 均为 JDK 21 |
| Windows 找不到 `uv` / `mvn` / `java` | 安装后重开 PowerShell，检查 `PATH`；`JAVA_HOME` 指向 JDK 根目录，不能指向 `bin` |
| Windows 测试无法创建符号链接 | 少数路径边界测试需要符号链接权限；启用 Windows 开发者模式或在有该权限的终端运行测试，普通页面启动不需要此权限 |
| 连接平台失败 | 确认终端 A 服务在运行，TOML 地址与 `18181` 端口一致 |
| 页面没有 B10 历史比赛 | B10 全量日志未公开；固定演示使用 `serve_b08_demo.py`，真实页面读取自己的 `runs/` |
| 已完成运行尚无复盘 | 记录保存与报告生成是两个步骤；可在页面生成无模型统计，或选择座位点击“生成模型复盘” |
| 模型复盘提示密钥不可用 | 使用 `uv run --locked --env-file .env guandan-agent serve` 重启服务并加载已有密钥；不要把密钥填入网页 |
| 决策提示仅能查询部分历史 | 实时窗口或归档缓存可能已截断；按页面提示继续查询可用部分，缺口提示不能当作完整历史 |
| V1/V2 后续只走规则 | 查看共享调用额度、模型错误与截止记录；额度耗尽后会使用规则备选 |
| 测试尝试联网失败 | 普通测试禁止联网；依赖安装和平台下载应在测试前完成 |

课程专用的打包与报告流程见[运行与交付说明](交付/运行与交付说明.md)，其中部分路径指向原工作区的本地附件。
