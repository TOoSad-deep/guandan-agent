# 快速开始

所有命令从仓库根目录执行。先体验无密钥页面，再按需准备 Java 平台和模型配置。

## 1. 安装 Python 环境

需要 [uv](https://docs.astral.sh/uv/getting-started/installation/)，Python 固定为 `.python-version` 中的 3.12.13。依赖版本与下载来源由 `uv.lock` 锁定。

```sh
git clone https://github.com/TOoSad-deep/guandan-agent.git
cd guandan-agent
uv sync --locked
uv run --locked guandan-agent --version
uv run --locked guandan-agent config-check configs/local.example.toml
```

`config-check` 只读 TOML，显示生效配置和 `config_id`，不读取 `.env`、连接平台或调用模型。不要通过修改锁文件解决临时网络问题。

## 2. 无密钥页面演示

```sh
uv run --locked python scripts/serve_b08_demo.py
```

打开 [http://127.0.0.1:18080](http://127.0.0.1:18080)，可查看牌桌、决策与固定复盘数据，按 Ctrl-C 停止。端口被占用时可附加 `--port 18081`。这是读取 `tests/fixtures/web/` 的固定演示，不需要 Java、API 密钥或新对局。

## 3. 获取固定平台并运行测试

公开仓库不携带第三方源码。获取脚本只下载固定提交、验证摘要并还原文件，不运行下载的代码。

```sh
uv run --locked python -m scripts.fetch_platform
uv run --locked pytest
uv build
```

上游：[OpenGuanDan-Simulator](https://github.com/GameAI-NJUPT/OpenGuanDan-Simulator)。固定提交：`e92db7fa9d915fb318b3be78703d5ccd4a09c887`；归档 SHA-256：`cb4015c37a4c19e5e6f59d856ee98e1d5a3f5708e46f86411ee4267e790fddc5`。

下载后分别放到 `research/archives/OpenGuanDan-Simulator-e92db7f.tar.gz` 和 `research/sources/OpenGuanDan-Simulator-e92db7f/`。已存在的有效快照只校验，不重复下载；本地内容改变时拒绝覆盖。摘要不匹配时先检查网络和来源，不要改常量跳过检查。

`pytest` 使用固定回放与 Mock，不启动 Java 或调用模型，并主动阻止网络连接。它会检查平台快照和原始文件，故需先获取平台。`uv build` 生成 `dist/` 下的 wheel/sdist，安装包只包含正式 Python 包及必要安装文件，页面演示脚本与平台构建需在 Git 检出目录执行。

## 4. 构建 Java 平台

需要 **JDK 21（java 和 javac）及 Maven**。首次 Maven 构建需要下载依赖。

macOS 可先查询 JDK 目录：

```sh
/usr/libexec/java_home -v 21
```

然后构建，路径按本机修改：

```sh
uv run --locked python scripts/prepare_platform.py \
  --java-home /Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
```

Linux 等环境可使用 `--java-home "$JAVA_HOME"`，前提是该变量指向 JDK 21。脚本在 `runtime/platform/` 创建运行副本和 Maven 缓存，只将副本的服务监听改为本机地址。它不改原始快照，也不启动对局。依赖齐全后可使用 `--offline`；全新安装不要直接加此参数。

## 5. 启动 V0 规则比赛

终端 A 从项目根目录启动刚构建的服务，确保此处的 `java` 来自 JDK 21：

```sh
java -Dserver.port=18181 \
  -jar runtime/platform/workspace/guandan-websocket/target/guandan-java-pure-1.0.0.jar
```

终端 B 执行四座位 V0，最多运行 120 秒：

```sh
uv run --locked guandan-agent run configs/local.example.toml --max-runtime-s 120
```

V0 不读取模型密钥、不发模型请求。日志写入 `runs/<run_id>/`；Ctrl-C 或达到演示时长后受控关闭。未取得整场结算的中断不能计作输赢，CLI 可能以非零状态结束。结束后停止自己启动的 Java 服务。

浏览新记录：

```sh
uv run --locked guandan-agent serve
```

打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)。默认本机监听，页面仅允许启动指定配置。服务本身不生成离线模型报告；查看已有记录不需要保持 Java 服务运行。

## 6. V1/V2 与模型配置

正式 CLI 从进程环境读取 `DEEPSEEK_API_KEY`。可先复制空样例并在本机编辑：

```sh
cp .env.example .env
cp configs/local.example.toml configs/my-v1.toml
```

在 `configs/my-v1.toml` 中把 `[run] policy` 改为 `"V1"` 或 `"V2"`，为一个新实验明确设置 `[batch] max_model_calls`，例如先用 `2`。四个座位共用 run 额度；V2 每步至多两次，失败调用也占额度。仅想让一个座位使用模型时，参考 `configs/b10-v1.toml` 的逐座位 policy 配置，并另存为新的 development 配置。

先检查再启动；启动前需要第 5 节的 Java 服务：

```sh
uv run --locked guandan-agent config-check configs/my-v1.toml
uv run --locked --env-file .env guandan-agent run configs/my-v1.toml --max-runtime-s 120
```

第二条命令会消耗真实 API 额度。模型名、超时和输出限制以 TOML 为准，`.env` 中的历史探针变量不覆盖正式 `RunConfig`。在线默认关闭思考、不重试。High 文本实验使用了更宽的超时和输出预算，不能直接当在线生产配置。

`b06`、`b09`、`b10` 等历史配置用于记录已完成实验；历史批次的 live 额度已使用，另开实验应有新的配置、额度、输出路径和停止条件。

## 7. 统计与离线复盘

对自己的已关闭归档重算统计，不需要模型：

```sh
uv run --locked guandan-agent evaluate runs/YOUR_RUN_ID --unit match
```

将 `YOUR_RUN_ID` 替换为实际目录。统计会区分整场与小局，保留中断、未确认和缺失值。

检查离线复盘计划：

```sh
uv run --locked guandan-agent review configs/offline-facts.example.toml runs/YOUR_RUN_ID
```

没有 `--live` 不生成模型回复。真实复盘需另存新配置并设置有限的 `[offline] max_model_calls`，加载密钥后显式附加 `--live`。程序事实会重新对照源记录；模型分析和建议仍需人工核对。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `Pinned archive missing` | 先执行 `python -m scripts.fetch_platform`；单独 wheel 不含平台源码 |
| 摘要不匹配或源码被改动 | 保留本地修改，核对上游固定提交；不要改 SHA 常量或覆盖原记录 |
| Maven/JDK 版本错误 | 确认 `--java-home`、`java -version`、`javac -version` 均为 JDK 21 |
| 连接平台失败 | 确认终端 A 服务在运行，TOML 地址与 `18181` 端口一致 |
| 页面没有 B10 历史比赛 | B10 全量日志未公开；固定演示使用 `serve_b08_demo.py`，真实页面读取自己的 `runs/` |
| V1/V2 后续只走规则 | 查看共享调用额度、模型错误与截止记录；额度耗尽后会使用规则备选 |
| 测试尝试联网失败 | 普通测试禁止联网；依赖安装和平台下载应在测试前完成 |

课程专用的打包与报告流程见[运行与交付说明](交付/运行与交付说明.md)，其中部分路径指向原工作区的本地附件。
