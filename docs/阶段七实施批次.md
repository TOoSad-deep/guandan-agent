## 3. 验收如何收口

### B04：保留规则整场作为平台基础

新客户端应完成一整场 V0，检查跨局、动作确认和结算。未自然出现的抗贡等分支通过历史真实帧回放补覆盖，不为等待稀有事件无限开场。阶段三旧探针记录不能替代本次新客户端运行。

### B06：只验证必要的真实主调用链

至少取得一条真实平台请求对应的模型动作及服务端确认。固定校准只用于排查接入，直接取得真实确认链后可省略。短验证达标即可安全停止；人为中断不是胜负，不拿它做策略成绩。

首次预算最多 1+4 次，未达目标时保留待验收并修复问题，不自动补额。最终 V1 整场由 B10 完成。

本批已在 run `bc3e0869-16ff-4738-ba10-27e155f03851` 取得 1 条真实主调用确认链：平台调用 1/4、校准 0/1，总计 1620 tokens；安全停止并标记 development/interrupted，不计胜负。277 个合法动作筛为 12 个候选，原始 notify 确认 `L0187`；审计记录（原工作区 `runs/bc3e0869-16ff-4738-ba10-27e155f03851/reports/b06-audit.json`） 与 [实施计划第 7.8 节](实施计划.md) 保存证据。模型简短理由有牌型描述误差，未把合法选牌等同于解释质量。

### B07：分支测试与自然实局覆盖分开

脚本模型确定性覆盖普通、复核、修复、失败、迟到和截止路径；主建议与备用使用不同编号，才能验证实际选择。随后最多两次真实调用检查固定场景的 main/review 输出；合成输入须标注，不冒充真实平台对局。

自然实局中的有效 `role=review`、`kept/changed`、`source=review` 且平台确认，作为 B10 的覆盖观察项。未自然出现就记录未覆盖，不让页面和统计开发停工，也不能说该路径已真实通过。若真实模型接口报错或输出无效，记录该项待验收；代码错误继续修复，补测另给有限额度。

B07 实际已完成 637 项本地检查，并在 run `74b55655-3b11-4e6a-bdf4-7420f28bc6d5` 取得真实 main/review 两次输出；复核从单 K 改为9炸弹，记录 changed，合计1822 tokens。固定场景记录（原工作区 `runs/74b55655-3b11-4e6a-bdf4-7420f28bc6d5/reports/b07-fixed-review.json`） 明确 `real_platform=false`，自然实局复核仍未覆盖，无新官方平台比赛。

### B10：集中做完整对比

完整实局首轮共四场：B04 一场，加 B10 三版本各一场。B10 必须使用冻结后的最终版本，不能直接拿 B04 的临时 V0 结果比较。首批固定座位且无可靠整场固定发牌，报告定位为描述性比较，列出模型参与量、规则降级量与覆盖缺口。

## 4. 适量测试与 Review

执行顺序保持：**实现 → 相关测试 → 针对改动的 Review → 必要修复与复验 → 更新执行记录。**

- 按实际改动选测试：规则改动检查规则，Session/预算改动检查相应下游，页面修改不重跑模型整场。
- 一次测试或实跑可以覆盖多个 AC/T。31 个 AC 与13 个 T 是场景索引，不等于必须写44个独立测试程序，更不等于44次模型调用。
- Review 聚焦本批改动，通常一次即可；发现具体问题再修复、复验。无新变化且检查已通过，不重复全库 Review 或整套实跑。
- 对纯文案、小配置或低影响展示修改，可以直接自检；状态、预算、提交及信息隔离改动应做针对性 Review。
- 记录任务状态、命令/步骤、证据路径和实际用量；更新 [实施计划第 7 节](实施计划.md)，不另建重复结果账本。
