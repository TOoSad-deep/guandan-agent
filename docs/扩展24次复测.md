# 扩展24次复测

> 公开版本说明：本文中标为“原工作区”的材料未随仓库提供；可公开核对的内容见[证据说明](evidence/README.md)。

日期：2026-10-19。用户认为此前3次定点复测不足，要求拓展场景并增加次数。本轮冻结12个任务，每个重复2次，共24次真实DeepSeek调用；运行期间不修改代码或提示词。

**结论：调用、合法候选和程序事实均通过；模型自由文字仍不稳定，问题主要集中在离线复盘。24份文字中，14份未发现明确事实错误、6份有明确错误、4份含混。**

## 扩展范围

| 维度 | 本轮覆盖 |
| --- | --- |
| 调用角色 | 8次main、4次review、12次offline |
| 案例与重复 | 4个main任务、2个review任务、6个offline任务，各重复2次 |
| 原始状态 | 9个唯一请求：2个旧请求、7个此前未实测的新请求；旧还贡请求同时用于main与offline |
| 座位与级牌 | 四个座位；级牌2、3、5、6、8、T、Q |
| 牌张问题 | 无配牌、实际持有一张/两张配牌、大小王、相同实体牌重复、候选扣减后的余牌 |
| 游戏情境 | 出牌、进贡、还贡、残局、队友领先、三连对、钢板、炸弹 |

新增实例包括：座位1打T且持两张HT；座位3打Q、使用HQ组成钢板；座位1用C8×2与D8×2组成炸弹，15→11张；座位3打8进贡；不同座位的对手剩2张残局。

这些是同一B04归档比赛中不同座位、轮次的请求，不是9场或24场独立比赛，也不是严格统计意义的holdout。每个模型请求只接收自身座位可见的输入；没有向平台提交新动作。

版本固定为在线 `b09-facts-v3`、离线 `b09-offline-v3`，模型 `deepseek-flash`。每次最多20秒，输入24,576字节，在线输出384 tokens、离线1600 tokens。review使用同一重复轮次的真实main结果，并用生产 `detect_risks` 重算风险；无有效main或无风险时跳过，不补次数。本次无需跳过。

## 分层结果

| 检查层 | 结果 |
| --- | --- |
| 真实调用 / HTTP传输 | 24 / 24，零重试、零供应商错误 |
| 生产输出契约 | 24/24通过；在线动作均在候选内，离线结构和引用归属通过 |

| 在线main/review理由 | 11条未发现明确错误、1条明确错误 |
| 离线模型分析/建议 | 3条未发现明确错误、5条明确错误、4条含混 |
| 模型文字合计 | **14条未发现明确错误、6条明确错误、4条含混** |

“未发现明确错误”只评价实际写出的陈述，不表示所有目标都验证完毕。正常决策理由没有强制逐条答题，例如两张HT的数量并非每次都明确说明；未提及的目标没有算作理解正确。程序生成的正确事实也不计入模型文字成绩。

三路子代理分别独立审计动作、离线r1、离线r2；另交叉审一条Q配牌案例，双方均保留为含混，不重复计数。root对照原文和证据汇总，保留各审计原件。

## 六份明确错误

| 回复 | 问题 | 原始事实 |
| --- | --- | --- |
| `main_back_baseline_r2` | 还出D2后仍说“保留对2结构” | 本人只有H2和D2，交出D2后仅剩H2；程序已给出2→1 |
| `offline_lead_baseline_r1` | 候选钢板T-J“消耗两枚10” | 该候选含CT、DT、DT，共3张10 |
| `offline_lead_baseline_r2` | 三连对未拆散6的对子/三张结构 | 该动作使6从3张降到1张，7和8各由2降到0 |
| `offline_duplicate_bomb_r1` | 将两条事后记录说成“本人后续领出” | 所给记录仅是本次炸弹确认与下一座位PASS，没有后来本人再次领出的证据 |
| `offline_partner_leading_r2` | 把本人座位1的PASS归给对手座位0，并混淆当时/事后 | e2655是本人PASS；座位0的PASS已在请求时历史里，e2668才是事后座位2的PASS |
| `offline_wildcard_q_r2` | 错说同花顺保留HQ、写错候选后的A花色和候选数量，并出现“后续摸牌” | 同花顺候选消耗HQ；输入实际提供6项候选并给出各项剩牌；掼蛋本局没有摸牌步骤 |

另四份含混结果保留原判定：进贡报告重复写第1名但括号又给出正确顺序；Q配牌报告“压过1个级别”等措辞不清；队友领先报告的先后范围不清；还贡报告“两张3中仅H3…不在手中”的语句含混。没有将主观策略分组或“散牌结构”等措辞一概强判为算错。

引用也要分层：引用ID合法不代表所指事件支持文字。比如还贡r1的D2执行事实本身正确，却将请求事件e1309直接标为确认依据；此类问题在独立审计中另列，程序补齐报告事实引用不替模型原始引用背书。

## 复核观察

4次review均使用本轮实际main，风险均包含 `OPPONENT_NEAR_FINISH`，均维持主动作。座位1的同一残局，main在r1选小王、r2选大王，两次review分别维持各自建议。

两种选择均合法，现有证据不判哪种更优。这说明本轮没有观察到review改选或纠错，也不能仅凭“调用了复核”宣称策略更可靠。
