# 掼蛋 Agent 实施计划

> 公开版本说明：本文中标为“原工作区”的材料未随仓库提供；可公开核对的内容见[证据说明](evidence/README.md)。

版本：v1.18，B10 最终评测与技术交付；个人报告及教师条件待成员确认。更新日期：2026-10-20，Asia/Shanghai。

## 1. 计划依据、范围与当前状态

本计划将 [需求与接口规格 v1.10](需求与接口规格.md) 和 [架构与技术选型 v1.7](架构与技术选型.md) 拆成可分工、可验收的任务，推进顺序沿用 [开发流程](开发流程与阶段产出.md) 的 M1—M5。**B01—B09 的 P01—P21 工程与流程验证已完成；B09 真实复盘生成/浏览/引用跳转通过，但自然语言事实准确性抽查未通过，不能把原报告当作可靠事实摘要。P22/P23 已完成：三版本实局均结束，8 次真实复核获确认。P24 的运行说明、报告、PPT、交付包与干净目录复现已准备；个人报告尚待成员据实填写，正式课程条件仍未知。模型文字质量限制继续披露。** 实际结果见第 7.2 节，任务定义与后续验收门槛保持不变。

第一版仍为三人课程项目：官方 Java 比赛服务、单进程 Python、DeepSeek、每请求 LangGraph、规则工具、基础网页、JSONL 和离线复盘/评测。不训练模型，不加入复杂搜索、数据库、分布式服务或自动策略改写。

阶段三已有正式源码快照的探针验证，阶段五已确定接口并修复三项契约问题：新局全量初始化、已接收事件先同步应用、再检查副作用、复核未开始时保留已登记主建议。这些是开发依据；阶段三的旧规则整场和四次模型请求不能抵作新客户端的验收。B01 已建立正式工程与 Java 构建入口；B02 已实现平台适配、临时 V0 与基本日志，完成本地模块交接。B03 已接通运行闭环，B04 已完成本地官方快照真实 V0 整场；B05 已实现候选工具、调用权威和 V1 图并通过本地/HTTP Mock。B06 已完成新版 V1 真实短确认链；B07 完成 V2 分支、联合截止测试与真实模型固定场景抽查；B08 已完成 HTTP 与页面；B09 已实现离线复盘与统计并完成真实流程验证，生成文本事实质量未通过抽查；B10 已完成最终三场评测与技术材料，个人报告与正式课程确认待成员完成。

尚未提供实际成员姓名、截止日期及可投入工时，本计划使用 A/B/C 责任角色，按依赖和交付批次安排，不编造具体日期或工期承诺。人员可替换，任务责任与验收条件保持不变。

## 2. 分工与工作约定

| 角色 | 主要责任及文件范围 | 协作要求 |
| --- | --- | --- |
| A：平台与运行 | `contracts.py`、`config.py`、`app.py`、`cli.py`、`runtime/`、`platform/`、平台构建入口 | 维护唯一公共结构、Session 事实、预算和发送权限；主导集成。B/C 提接口变更，不复制状态或预算实现 |
| B：规则与 Agent | `hand/`、`strategy/`、`model/`、提示词 | 实现廉价规则、候选工具、模型接入及 V1/V2；只取本座位输入并返回建议。A 提供受限 CallPort/SendGate，不把 Session 可写引用交给策略 |
| C：记录与展示 | `recording/`、`web/`、`offline/`、实验记录与交付索引 | 从 M1 接入最小日志；后续实现查询、页面、复盘与统计。结算和提交事实仍来自 Session/平台 |

任务表中的“负责”是唯一主责角色，括号是协作角色。模块实现与对应测试由同一主责人维护；涉及公共契约或多模块时，由 A 统一合入结构变化，B/C 补相应样例和断言。所有模块通过注入的真实/脚本实现联调，不能为绕开依赖自行搭第二份平台状态、调用计数或日志账本。

本版保留 24 个任务编号和十批安排，缩小每批的必做范围：不做业务队列序号追赶、日志修订链、工具自动恢复；V1/V2 开发期只做短链路验证，完整实局集中到最终评测。批次入口见 [阶段七实施批次](阶段七实施批次.md)。

开发与验收状态统一为 `待开始 / 进行中 / 待验收 / 已验收 / 受阻`；进入“已验收”需给出源码版本或文件摘要、实际命令/步骤、结果和证据位置。阶段三旧文件只能作为参考输入。测试与 Review 只覆盖实际改动和受影响路径，检查通过且无新变化时不重复整套实跑；每个任务完成时更新本文第 7 节的执行记录，不只在聊天里说明“完成”。
